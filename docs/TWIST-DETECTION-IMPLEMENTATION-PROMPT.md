Objective

Build an optional offline stage that estimates total longitudinal twist per flight from the original source video plus saved tracking. Return a supported count only when the temporal evidence distinguishes plausible alternatives. Preserve null/unknown for insufficient evidence, with a separate tentative candidate and reasons. Target upright twists and twisting somersaults, including seat transitions. Initially prioritize total turns; distribution across successive somersaults is a separate later task. Distinguish observed execution from intended skill names and user references.

Research conclusion

The recommended first experiment is video-informed 3D torso orientation plus temporal multiple-hypothesis decoding. SAM 3D Body is the first image-based backend to assess; GVHMR is a useful contrasting video-based baseline if runnable. This is an engineering recommendation, not evidence either already counts trampoline twists accurately. Compare against a cheap 2D baseline and choose using held-out counts and prediction coverage. Single-camera depth/occlusion ambiguities may remain irreducible. Future synchronized calibrated complementary cameras offer a stronger measurement route, but do useful work on existing footage first.

Primary sources and practical findings

1. https://arxiv.org/pdf/1709.03399 — Connolly et al., 2017, direct trampoline work. Uses normalized shoulder separation as a feature in a skill classifier; 80.7% reported skill classification is not twist-count accuracy. Useful baseline, insufficient as a standalone counter.
2. https://arxiv.org/html/2604.01322v2 — 2026 trampoline-specific ViTPose-S fine-tuning study. Improves multi-view joint reconstruction, not demonstrated monocular twist counts. https://github.com/VisionICLab/trampoline_syn_data currently says code will be available soon; verify availability before relying on it.
3. https://arxiv.org/abs/2602.15989 and https://github.com/facebookresearch/sam-3d-body — SAM 3D Body. Its estimator accepts existing bounding boxes and optional masks/intrinsics and returns 3D joints/rotations. Inspect exact MHR joint, axis, unit and rotation conventions. Paper prompt support may differ from the convenience API. Independent frame outputs need temporal disambiguation. Check gated weights, license, memory, dtype and CUDA assumptions; do not promise GTX 1070 compatibility.
4. https://arxiv.org/html/2512.08406v1 — SAM-Body4D addresses image-HMR temporal inconsistency using masks. Possible follow-up, not a prerequisite for our already-tracked single athlete.
5. https://github.com/zju3dv/GVHMR — temporal 3D comparator; static-camera mode avoids visual odometry. Separate Python 3.10/PyTorch dependencies and registered body assets. Source license is educational/research/nonprofit; evaluate contact/ground priors on airborne motion. Inspect official install docs and LICENSE.
6. https://arxiv.org/html/2604.17818v1 and https://github.com/awfuact/anylift — AnyLift targets gymnastics motion, but its gymnastics metrics do not establish twist accuracy; checked repository contains project-page assets, not verified inference code. Recheck availability but do not block on it.
7. https://isbweb.org/standards/yeadon1.html — Yeadon's whole-body somersault/tilt/twist convention. Establish a documented biomechanical orientation definition before counting.

Implementation sequence

1. Audit available source videos, exports, flight boundaries, annotations and hardware. Locate original video through saved job/source records and verify its SHA256 against joints. Record which observations and labels are actually available. Existing hardware report says Windows, GTX 1070 8 GB and about 16 GB RAM; check current state. Use a separate inference environment/process for a new 3D model, never upgrade the existing tracker environment in place. Perform a bounded model compatibility/inference smoke test before processing full videos. Record exact versions, checkpoint/config hashes, license/access requirements and measured memory/runtime. If assets/access/hardware prevent actual model inference, finish the decoder, adapters, evaluation harness and actionable blocker report, but explicitly state that real inference remains unverified. Do not disguise synthetic outputs as model results.

2. Create a reproducible annotation/evaluation manifest and native-frame review sheets for representative flights. Separate human-reviewed measurements, user references and detector predictions. Include visible intermediate chest/back/side orientation where feasible, actual total twist turns, label certainty, and boundary intervals. Reserve independent athletes/sessions for evaluation if available; otherwise report development-only evidence and the exact missing data. Include strong negative controls: non-twisting front/back somersaults, head turns, arm movement and left/right errors. Include full/higher twists, not just the existing half-twist examples. Do not infer zero twist from an absent label.

3. Implement a small backend-neutral orientation sidecar and pure twist decoder. Preserve native source PTS/frame IDs, athlete identity, crop transforms, validity, uncertainty and model provenance. Handle fixed-camera coordinates first. If using rotated crops for inverted poses, invert both image-coordinate and 3D camera-frame transforms correctly; a 2D point transform alone is insufficient. Reuse the athlete's saved boxes rather than allowing a second detector to switch people. Do not invent estimates across tracking loss. Cache by all inputs/configurations that affect results.

4. Define a right-handed torso/body orientation frame, justify its relation to sport twist, and document the somersault reference axis, rotation order and sign convention. Use matrices/quaternions internally, derive a Yeadon-style somersault/tilt/twist decomposition or justify a validated equivalent. Compare upper-torso and pelvis orientation; root rotation alone may miss trunk torsion or misrepresent a pike. Upright jumps need a suitable heading branch when the somersault axis is unobservable. Explicitly detect singular/degenerate cases. Do not substitute world yaw, 2D shoulder crossings, endpoint facing, shortest quaternion distance or an unqualified swing-twist decomposition. Integrating omega dotted with the body axis is not generally the same as the sport twist coordinate during combined somersault/tilt.

5. Decode a continuous, unwrapped twist history using native elapsed time and competing winding-number/side-assignment hypotheses (e.g. beam search or dynamic programming). Score image/3D evidence, geometric consistency and plausible temporal motion without enforcing constant speed or forcing twist into every flight. Handle front/back ambiguity, transient anatomical side swaps, quaternion sign equivalence, gaps, clipping, temporal aliasing and genuine reversal. Do not smooth away real rapid turns or force a count through an ambiguous gap. Same endpoint facing cannot distinguish zero/full/double twists. A low reprojection error is necessary evidence but cannot resolve all monocular depth ambiguity. Use head/face appearance only as supporting evidence; head and torso rotate independently.

6. Export versioned evidence with nullable supported count, candidate count(s), unrounded angular displacement, optional direction, method/status, coverage, boundary sensitivity and reasons/supporting intervals. Keep raw evidence and any reconstructed motion distinguishable. Do not round to half turns unless the angular evidence and hypothesis separation support that classification. Net displacement and total absolute rotation differ when reversing; specify semantics and flag ambiguous reversals. Confidence-like heuristic scores are not calibrated probabilities. Conflicting shoulders/pelvis or uncertain flight endpoints should lower support or cause abstention.

7. Test actual failure risks using generated 3D rotation sequences with known somersault/tilt/twist and independent expected outcomes: zero/half/full/higher twists, combined rotations, nonzero tilt, tilt changes without intended twist, upright and inverted poses, pike/trunk disagreement, quaternion sign changes, coordinate/crop rotations, camera changes where supported, synthetic side swaps, dropped/VFR frames, singularities, aliasing and real reversals. Test source/hash/cache mismatches and backward-compatible unknown display. Synthetic passing tests establish geometry/software behavior only.

8. Run the 2D baseline and available real 3D backend(s) on identical reviewed flights. Report exact-count confusion, false-positive twists on zero-twist flights, half-turn error rate, coverage, selective accuracy versus coverage, failures by pose/view/blur, runtime and peak memory. Avoid per-frame Procrustes alignment as evidence of correct global orientation. Declare thresholds and data partitions before reporting held-out results. Do not train an appearance classifier on a tiny familiar routine and call it general. Prefer the simplest backend that demonstrably improves count accuracy at useful coverage; no model wins by default.

9. Integrate the chosen approach behind an optional experimental CLI/portal path once real evidence justifies it. Preserve saved joints and current analysis behavior when disabled or unavailable. Display supported twist, tentative candidate and unknown distinctly; skill names must consume only supported counts. Keep reference annotations separate and repair any seat-transition naming path that otherwise bypasses the twist evidence policy. Run relevant existing regression checks. No deployment or public footage upload is requested.

Deliver working code where feasible, review artifacts, documented commands, a source-linked decision report, actual test/evaluation results and an honest limitations/data-needs list. Report real-video counts separately from synthetic tests. If no method achieves dependable counts, deliver the experiment and explain the capture/training changes supported by its failures; do not manufacture a confident detector.
